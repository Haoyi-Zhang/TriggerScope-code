# Validation design and interpretation

The main campaign has exactly 2,448 cases. Each case builds a semantic DAG, produces an omission certificate, invokes the separately written checker, solves one independent circulation problem for every candidate outcome, and validates the constructed allocation's actual outcome. Failed cases would stop a chunk rather than be silently removed. No fitting, held-out tuning, selective exclusion, or favorable-result requirement is used.

## Exact finite oracles

The capacity group exhausts two complementary matrix shapes with entries in {0,1,2} and nonzero class columns. The 2-by-3 domain contains 512 matrices, 9,584 valid bucket-count reports, 110,592 labelled-token subsets, and 19,456 outcome-specific allocation witnesses. The 3-by-2 domain contains 676 matrices, 19,252 reports, 116,964 subsets, and 26,488 witnesses. Combined, the suite checks 1,188 matrices, 28,836 reports, 227,556 concrete subsets, and 45,944 witnesses. Exact outcomes are compared with both the prefix and independently coded circulation implementations; every constructed witness is checked directly for row sums, cell bounds, and its resulting first omission. The paired shapes prevent a test domain with more classes than buckets from hiding row/class asymmetries. Source-derived classes are likewise nonempty.

The source group enumerates 20,832 instances from a precisely bounded grammar: twelve primitives over two event kinds; one-monitor identity/negation; ordered two-monitor combinations with five fixed Boolean output forms; horizons 0..3; valid minimum lengths 0/1; both environment flags; moduli 1/2. It directly evaluates 113,088 legal words and compares counts, nonempty classes, canonical representatives, and certificate replay. This is exhaustive for the named domain, not all possible small programs.

The mutation group starts with 55 unmodified certificates from the five families, including longer horizons. It tests changed counts, absent or duplicated nodes, guard confusion, capacity changes, representative/class-order changes, incorrect prefix length/cut/matching, altered spectra/verdicts, invalid report counts, and invalid allocation witnesses. The 729 non-equivalent mutants must be rejected; 55 reordered-but-equivalent controls must be accepted. This suite is not a proof that every malformed input or every common-mode semantic error is detected.

## Deterministic capacity stress

The `stress` group uses seed 9142026 to generate 20,000 additional capacity/report instances with one to five buckets, one to eight nonempty classes, and cell capacities from zero through five. Five fixed report modes cover zero, full, half, one-per-row, and uniform-random row counts. The prefix implementation is compared with the independent circulation solver for every case. For every certified outcome, the producer constructs an allocation that is checked directly against row sums, cell bounds, and the resulting first omission. The retained run checks 54,276 witnesses, reaches 133 labelled tokens and a nine-outcome spectrum, and records zero disagreements. This is deterministic implementation stress, not an exhaustive domain or statistical claim.

## Negative controls

The source-grounded ambiguity control has capacity [[1,1],[1,1]] and counts [1,1]. Its possible first omissions are class 0, class 1, and COMPLETE. The Hall control has capacity [[1,1,1,0],[0,0,0,3]] and counts [2,2]. Its possible first omissions are 0,1,2; no complete realization exists even though total reported traces equal the class count and each class is individually possible. Full models, certificates, and exact subset counts are in `results/tests/controls.json`. These controls are outside the 2,448 primary instances and are reported separately.

## Baseline definitions

Bucket-label coverage asserts complete when every bucket has a positive report count. The cardinality proxy asserts complete when total counts reach the number of classes. Marginal possibility asserts complete when every class has an incident positive-count bucket. Existential full-cover feasibility asserts complete whenever SOME compatible allocation covers everything. The last is an exact existential property but an unsound substitute for universal evidence. The circulation baseline, by contrast, computes the entire exact spectrum; it is a valid exact comparator, not a proxy.

`not_entailed` counts proxy assertions not forced by the evidence. `false_for_constructed_report` counts assertions contradicted by the particular authored allocation. These are distinct: a statement can happen to be true of the authored allocation yet not follow from its disclosed counts. Exact class-allocation disclosure always fixes the outcome, by the allocation lemma; the replay command checks that allocation as evidence, not as a competing detector.

The no-Hall ablation permits every individually avoidable class and always permits COMPLETE. The no-exclusion ablation permits every candidate allowed by prefix length. The complete primary suite has no difference between the count-threshold proxy and existential full-cover feasibility; the isolated Hall control supplies that distinction. Do not read the no-Hall ablation's disagreements as showing Hall-specific discrimination across the primary distribution.

## Resource counters

CPU and RSS are directly observed process resource values. The checker-step counter counts semantic event transitions considered plus one step per capacity cell in the final exclusion scan; it does not count every comparison, witness check, parsing operation, or interpreter instruction. Explored layered nodes refer to producer construction; replayed nodes are not newly explored states. Raw resource records and a cumulative budget account distinguish construction from replay and validation. Timing is descriptive for this implementation and run, not an architecture benchmark. The certificate-construction timer excludes semantic DAG generation, while full-case time includes generation, checking, baseline solving, and result handling.

The checker and producer have different source implementations and do not import each other's semantics/search routines. Both were authored in the same environment and use the same Python implementation. This is implementation separation, not independent human or proof-assistant validation.

Two source-grounded report-binding controls supply a complete, internally consistent certificate for a different valid count vector. The checker accepts it with that vector and rejects it with the declared vector. The independent replay reads frozen counts from `data/reports.jsonl`, not from an optimizer or an untrusted certificate alone. Counts were extracted from the authored primary reports and frozen as semantic inputs; they are not external authenticated logs.

## Overlap-boundary validation

The `overlap` group checks the X3C reduction independently of the omission-spectrum implementation. It enumerates every subfamily of size at most four from the twenty three-element subsets of a six-element ground set, discarding only families that omit a ground element. Direct exact-cover enumeration is compared with a brute-force 0--1 solver for the resulting exact-count views. The retained result records 4,090 families, 1,675 feasible families, 2,415 infeasible families, 1,720 compatible selections, and zero disagreements. A JSON round-trip checker that does not call `normalize_x3c` reconstructs the views and re-enumerates compatible selections for all 4,090 retained families. Every one of the 1,720 positive selections is then interpreted only against the saved canonical token list and checked to count every canonical element exactly once. The two named controls use deliberately unordered element, token, and within-token input; retained selections index only canonical `tokens`, while explicit input-to-canonical and inverse permutations preserve the raw order. The theorem is still established by the reduction proof, not by these finite cases.

The separate `tests.test_overlap_totality` unit suite exhausts the 2,106 uncovered-element families omitted from the retained overlap domain. Both direct X3C enumeration and exact-count feasibility must return no selections, and `reduction_agrees` must return true. Additional controls distinguish valid infeasibility from malformed shapes, indices, or counts and require validation of later rows even after a local obstruction. This regression is not added to the original 4,090-family experiment denominator; its run results are separate from `results/tests/overlap.json`.

## AndroLog-format adapter validation

The `androlog` group converts seven authored session files through an injective eight-probe map. Two byte-distinct files have different timestamps but normalize to the same complete event trace, so seven files yield six distinct traces. The derived count vector is `[0,1,3,1,0,0,1,0]`; its certificate has ten classes, spectrum `[0,1,2,3,4]`, and a forced-incomplete verdict. The exact authored allocation has first omission 1, which lies in the spectrum. A positive duplicate-normalization control confirms that byte-distinct files with the same complete normalized trace collapse exactly once. A positive anchoring control places an unrelated assignment before the log identifier and confirms that only the assignment after the identifier is parsed.

The original 22 portable negative controls remain. Their aggregate-byte member is now branch-specific rather than a sparse oversized-file surrogate: two strict-UTF-8, NUL-free, individually valid 200-byte session files are accepted at a parameterized 400-byte total limit; after one file grows to 201 bytes, each file still parses separately and the same directory is accepted at 401 bytes but rejected at 400 bytes with the dedicated aggregate error. If the cumulative guard is removed, that rejection assertion fails. The other portable controls cover unknown/unsupported/malformed/NUL input, invalid identifiers and models, horizon overflow, empty/oversized/symlink/nonregular/excessive/invalid-UTF-8 session inputs, invalid probe-map syntax/range/type/injectivity, and oversized/symlink/nonobject/malformed JSON configuration. On POSIX platforms with `mkfifo` and `O_NONBLOCK`, two additional timeout-bounded child-process controls pass no-writer FIFOs as a session path and a configuration path. Both must return explicit `InvalidLog`, not pass through an external timeout, and the descriptor count must be unchanged where `/proc/self/fd` is available. A changed distinct session also demonstrates expected-count binding. This is syntax, resource-admission, and model-contract evidence only; it is not device, instrumentation, APK, provenance, or semantic probe-map evidence.
